# Owned direct-root mapped closure prerequisite

This private supervisor contract extends privacy-abi-v1 and
privacy-jni-ownership-v1. One original launch owner performs a complete bounded
inspection of its directly owned, stopped root. It is an implementation
prerequisite within the full fork/exec/client path, not an advertised width1
support matrix or complete runtime admission. Production installation tables stay
empty. The nine JNI signatures, mandatory missing-stage INSTALLATION refusal,
and absence of CHALLENGE/FinalAdmitted remain unchanged.

## Stop and execution boundary

Only the original correlated receiver may enter this operation, once, after fresh
PREPARE, kernel root/Java Process matching and completed launcher disarm. Hold the
existing primitive claim and original cancellation/startup clocks throughout.
First use waitid(P_PIDFD, WSTOPPED|WCONTINUED|WNOHANG), with zeroed siginfo, to check for any pending
stop/continue event; a nonempty result refuses instead of becoming this operation's
receipt. Then request SIGSTOP through the retained socket-bound pidfd. A matching completed
CLD_STOPPED/SIGSTOP event from waitid(P_PIDFD, WSTOPPED|WCONTINUED|WNOHANG) for that direct
child establishes the stop observation. Refuse a prior pending stop/continue
event, ECHILD, unexpected event, exit, signal refusal or original deadline.
Do not consume WEXITED, reuse WNOWAIT observations, replace the Java exit reaper,
or substitute a numeric PID lookup. Qualify actual JDK reaper coexistence.

Acquire a fresh proc directory and every maps/mem/exe/cmdline/auxiliary descriptor
used as closure evidence only inside that completed stop interval, with existing no-follow,
identity and bounded-read rules. Match the original live pidfd and process
identity around acquisitions and completion. A retained mem fd from an earlier
execution, one stopped thread, a blocked constructor, repeated equal maps or
elapsed time is not this evidence. No ptrace attach, new privilege, dumpability
reset or security/collector configuration change is permitted.
Existing pre-stop peer/root identity checks remain mandatory; their descriptors
and results cannot substitute for the fresh stopped closure acquisitions.

The stop observation alone cannot exclude an external SIGCONT followed by
change-and-restore, external shared-page/mm writes or a malicious kernel. This
prerequisite grants no new trusted-operator exclusion: the existing installation
trust boundary is unchanged. Its internal byte-comparison result is conditional
on uninterrupted exclusive process control. Any observed loss refuses; lack of
an observed loss is not proof that interference was impossible. Final identity
must remain unavailable until the full runtime mechanism and qualification
establish the required control/continuation conditions. A fixture may enforce
those conditions for its own bounded test; its result cannot certify an installed
client. Never turn the conditions into a caller/record boolean granting admission.

The direct parent's kernel stop event does not establish a descendant's stop.
Non-child peers refuse this operation. Descendant control and post-inspection
continuation remain explicit complete-graph dependencies; neither is silently
approved or reduced to polling. Existing <=64 execs/width<=16 requirements remain.

## Closed compiled recipe

Only an immutable native table selected by the original admitted chain ordinal
may supply the recipe. Add a private lookup returning a const recipe or absence;
absence refuses INSTALLATION. No Java array, peer field, path label, environment,
callback, mutable setter or portable configuration supplies policy. The production
lookup returns absence until separate installation qualification exists. Test
recipes are independently invented and linked only into isolated fixture builds.

Recipe version1 fixes: Linux amd64 ABI/page size; direct-root node ordinal;
complete bounded required object list; each object's positive unique ordinal,
trusted absolute path and content digest; executable/interpreter/loader/guard
roles; every relevant mapped range/permission role; and typed byte/relocation
recipes. Counts and all offset/size/address arithmetic are checked before access.
Unknown versions, kinds, overlap rules or missing required fields refuse. Native
record representation is private; its implementation cannot weaken these meanings.

The initial recipe schema permits at most512 objects,128 ELF program headers and
32 load segments per object,65536 byte/relocation records across the whole recipe,
4095 UTF8 bytes per trusted path and8MiB total immutable recipe storage including
all referenced tables/strings. Page size is the qualified4096-byte amd64 form;
other forms require a separately reviewed extension. Every declared count must
agree with its static array extent and be checked before traversal.

Initial byte kinds are FILE (object/file offset), ZERO, LITERAL (bounded exact
compiled bytes), and RELOCATION. Relocations initially support ELF64 little-endian
R_X86_64_RELATIVE, R_X86_64_64, R_X86_64_GLOB_DAT and R_X86_64_JUMP_SLOT, using
their ABI-defined widths/formulas and checked overflow. Symbol forms require the
exact defining object and versioned symbol metadata; unresolved lazy slots refuse.
No generic mutable-region predicate is implemented by this version: such regions
must have complete FILE/ZERO/LITERAL/RELOCATION coverage or refuse. COPY, TLS,
IFUNC/IRELATIVE, other relocation kinds and anonymous/JIT executable recipes are
explicitly unsupported required evidence at this stage. Extending that mechanism
vocabulary is lead-owned contract work before dependent implementation, not a
reduction of required client/JVM qualification. A successful small fixture must
be complete within these forms and remain visibly distinct from an installed
glibc/client closure. The three closed kernel-special roles and ordinary NX role below are mandatory
coverage checks, distinct from file byte recipes and generic executable allowances.

Resolve objects by retained trusted file identity and validated mapped ranges,
never by treating map labels as filenames. Reuse the existing file/hash/image/
ELF/argv/script checks under this same owner. Every required object must be present.
Account for the entire mapped executable coverage, including interpreter, loader,
guard, page tails and aliases. Missing/unexpected executable mappings, ambiguous
load bias or incomplete object coverage refuse. Each PT_LOAD constrains the same
unique object load bias. Validate split mappings, page-rounded overlaps, file
offsets, zero-fill, protection changes and address overflow together; two matching
segment starts alone do not establish a complete image.

Every compared interval has an explicit typed role: exact file bytes; defined
zero/padding; independently calculated relocation bytes; or a named, implemented
mutable-region invariant. Roles must account for the whole required interval
without gaps or contradictory overlaps. Never exempt arbitrary writable pages,
RELRO/GOT or control state by a generic skip/ignore/any-value flag. Unsupported
mutable invariants refuse. This is a closed mechanism vocabulary, not inferred
application semantics or an invitation to commit actual installation facts.

Relocation recipes fix the ELF relocation kind, checked target offset/width and
addend, defining object/symbol/version and relevant TLS/IFUNC alternatives. Validate
the recipe against admitted ELF metadata. Compute expected bytes from admitted
file metadata and independently derived object layouts; compare actual memory.
Never execute a resolver/peer instruction in the supervisor or use an observed
pointer as its own expected value. Only explicitly implemented and tested forms
can succeed. An unsupported mandatory relocation, copy/TLS/IFUNC/lazy-binding
form refuses. Do not silently force eager binding or ban those features from the
intended product support matrix to simplify the fixture.

Special/anonymous mappings, vDSO/vsyscall, stack, later dlopen and JIT require
explicit qualified treatment. An absent file entry is never approval. The
complete-graph contract must establish early preinit/constructor/IFUNC behavior,
all secret-consuming threads and later loading/exec transitions. A PREPARE-time
snapshot cannot supply those lifetime guarantees. This prerequisite retains
missing-stage refusal even after every byte in its invented closure matches.

## Special and ordinary non-file coverage

The compiled runtime/kernel recipe separately accounts for kernel-provided
mappings; they are not invented installation files. Its exact kernel/ABI/image
identity and implementation semantics require independent qualification. A label,
version string, successful syscall, read error or peer claim cannot select or
qualify that record. All three roles use the same bounded stopped maps/auxv/mem
owner. Unknown kernel roles or contradictory/extra executable coverage refuse.

KERNEL_VDSO_IMAGE fixes native ABI, page/ELF layout, complete mapped byte extent
(at most64KiB), permissions and expected post-alternatives bytes or their complete
digest. Fresh stopped AT_SYSINFO_EHDR plus complete map/layout correlation selects
the target extent. Compare every actual byte, including executable tails, under
the shared work counter. The peer's own bytes cannot supply the expected digest.
For tests only, freeze the reference from an independently trusted pre-peer
native process before the child exists, record its provenance and link the result
into an external test fixture. A pre-peer reference is a host-kernel oracle, not
independently invented data: keep all host-derived images/records outside the
checkout and build context. Production requires separately qualified image
provenance; the production table remains empty. Kernel CPU alternatives mean an
unpatched on-disk vDSO artifact is not automatically the expected live image.

KERNEL_VSYSCALL_XONLY accounts for exactly one native64-bit,4096-byte kernel-emulated
gate at [0xffffffffff600000,0xffffffffff601000), with --xp, offset0 and kernel
pseudo-object device/inode0. The independently selected kernel record must fix
XONLY behavior and the same trusted supervisor/peer kernel context. Validate the
whole kernel-produced range, absence of conflicting coverage and independently
frozen pre-peer context. XONLY has no backing user-code page: this is kernel
semantic coverage, not successful byte equality or an EIO exception. Charge one
coverage occurrence and zero nonexistent mapped bytes. Readable EMULATE, NONE,
compat or unknown behavior refuses this initial role; no automatic fallback or
host configuration change is permitted. The explicit test-linked source-backed
kernel assumption is reported separately from actual installed qualification.

KERNEL_DATA_NX fixes the exact bounded kernel data range geometry, read/write/NX
permissions and association with the admitted kernel/vDSO layout, including the
qualified vvar/vvar_vclock forms when present. Their kernel-updated values are not
installation code bytes and are not compared to a stale literal. Never extend
this role to arbitrary anonymous writable mappings or executable data. Ordinary
stack/data coverage uses ORDINARY_DATA_NX below; it cannot hide a required object
or satisfy a mutable file-image interval by omission.
At most16 special/data role records and1MiB aggregate kernel-data geometry are
allowed in this initial recipe; records still count within the65536-record and
8MiB immutable total. These ceilings do not assert observed layout on every kernel.

ORDINARY_DATA_NX is a closed geometry/permission role for private, non-executable,
non-file-backed ordinary process data. Its discriminator is STACK or ANONYMOUS;
records fix allowed read/write bits, min/max page-aligned extent, allowed range
count and aggregate extent. STACK must contain the freshly read kernel exec
start-stack anchor and the inspected argv stack region; ANONYMOUS matches only
unclassified private inode/device-zero non-kernel ranges. Names/labels grant no
identity. Require exact declared counts/extent bounds and no overlap with any
required file-image or kernel-special interval. File-backed BSS/tails, a required
object's anonymous zero-fill and relocated/mutable file intervals must satisfy
their byte recipes first and cannot be reclassified as ordinary data.

At most16 ordinary-role records may classify at most256 ranges with at most1GiB
combined virtual extent in this initial direct-root prerequisite; these records
also consume the65536-record/8MiB immutable recipe totals. Extents are geometry,
not allocations in the supervisor. Every remaining map must match exactly one
declared role or required object; unknown, shared or executable ordinary mappings
refuse. The role asserts current NX geometry only, not benign data, control-state
integrity or future mprotect/JIT safety. Those remain complete-runtime/continuation
requirements; this explicit role cannot enable admission or a support reduction.

### Stopped smaps exclusion evidence

Before ordinary classification, acquire one fresh no-follow smaps descriptor
through the original stopped owner's pinned proc directory. Stream it against
the complete stopped maps snapshot. Require exactly one matching header and one
complete VmFlags field per maps occurrence, in the same order, including special
mappings. Header equality covers address interval, r/w/x and s/p, offset, device
and inode. Missing, duplicate, extra, reordered, contradictory or incomplete
records refuse. Names are bounded discarded labels, never identity selectors.

Both STACK and ANONYMOUS must exclude io, pf and mm (VM_IO, VM_PFNMAP and
VM_MIXEDMAP). Their absence is necessary negative evidence, not universal proof
of ordinary memory. Required file-image and independently admitted kernel ranges
take precedence; an ordinary role cannot absorb an omitted kernel role, including
one with compatible NX permissions or aggregate geometry. KERNEL_DATA_NX still
requires its independently selected complete kernel/vDSO geometry and context.
Flags alone never grant kernel identity. Installation qualification must establish
that every relevant kernel non-file form is independently covered or excluded;
this conditional prerequisite cannot certify an unknown kernel from absent bits.

For this Linux amd64 vocabulary, recognized VmFlags tokens are rd, wr, ex, sh,
mr, mw, me, ms, gd, pf, gu, lo, io, sr, rr, dc, de, lf, ac, nr, ht, sf, ar, wf,
dd, sd, mm, hg, nh, mg, um, uw, ui, ss, dp and sl. They are distinct two-letter
ASCII tokens; unknown tokens, ??, duplicates and malformed fields refuse.
Recognizing a token grants no new role or permission. Correlate rd/wr/ex with
the current r/w/x header bits. Linux's s/p header uses VM_MAYSHARE (ms), not
VM_SHARED (sh); correlate ms with that header and require both absent for an
ordinary private role. Do not substitute mr/mw/me for current access bits or
equate sh with ms. Other smaps counters may be streamed and discarded after
bounded line validation; they are not classification or identity evidence.

Stream at most16MiB input with an8192-byte line ceiling including its newline.
Require complete newline-terminated records and observed EOF; reaching the input
ceiling without established EOF refuses without an unbudgeted read. Reuse the
existing <=64KiB scratch; no second retained arena. Include line/parser state
and any per-occurrence flags in the unchanged1MiB active ceiling. Before open or
read, conservatively charge one occurrence and reserve16MiB against the same
512-occurrence/2GiB cumulative work owner; no refund, reset or second work budget.

All existing original clocks, cancellation, stop/identity checks and close-once
uncertainty apply. Missing/unavailable smaps, read failure, malformed/truncated
input or unsupported classification refuses with the existing typed reason.
A blocked or late kernel read retains its claim, buffer and descriptor until
actual return/closure; expiry cannot authorize reclamation or success. Preserve
the first operational refusal separately from sticky cleanup uncertainty.
Smaps may walk page tables: bounded output is not proof of bounded kernel work
or syscall duration. Exact installed-kernel resource/lifetime qualification is
still required; no assumption of interruptible reads or new trusted-control
exclusion is introduced.

Acceptance includes omitted one/all kernel-data roles; absorption by either
ordinary discriminator; legitimate named/unnamed ordinary NX ranges; file or
special overlap; missing/duplicate/reordered/mismatched headers and flags;
rd/wr/ex versus mr/mw/me and sh versus ms; known newer and unknown tokens;
truncated/overlong/ceiling reads; original deadline/cancel, held reads, descriptor
recovery and sticky uncertain close. Preserve mandatory missing-stage INSTALLATION
and no CHALLENGE/FinalAdmitted after any successful internal comparison.

Kernel-special checks are mandatory inputs bound to the existing compiled runtime
identity. They do not create fictitious inode/file hashes in ES_PRIVACY_CLOSURE_1:
that ordered installation-file object encoding is unchanged. An absent/failed
special check prevents internal closure success. The runtime identity and its
kernel record must pin these rules before future final admission; a file-closure
digest alone does not encode or prove kernel qualification.

## One owner, publication and cleanup

Extend es_launch; do not create a parallel coordinator, peer acquisition, listener,
clock, cancellation source, hash pool or admission callback. The receiver holds
one operation claim across stop acquisition, bounded inspection, output transfer
and all subordinate cleanup. Never hold a registry/owner mutex across blocking
syscalls or call Java while holding either mutex. Recheck the original deadline,
cancellation and phase after returning work and before publishing internal output.

The launch owns the stop obligation and all inspection capabilities. A failed or
incomplete prerequisite does not resume the process to normal work. Cleanup
terminates only the exact pinned/Java-owned process through the existing owned
cleanup path; the Java Process reaper retains its responsibility. Closing a pidfd
does not terminate or resume a stopped process. Verify actual process/three-pipe
termination separately from native descriptor closure.

Conclusive closure of every process-memory capability is required before any
future successful SIGCONT or CHALLENGE. Dumpability zero does not revoke an
already-open mem fd. The current production coordinator has no successful release
or challenge path: after an internal comparison it still refuses missing stages
and requests owned termination. Tests must observe this boundary through actual
production JNI and may inspect internal results only through test-linked probes.

Attempt every subordinate cleanup. A held/late read retains its primitive claim,
storage and descriptors; shortened close may return INCONCLUSIVE but cannot free
them or permit success. Record close uncertainty once without retrying a reused
descriptor number. Preserve the first operational refusal separately from sticky
cleanup uncertainty. Wipe failed/late output and temporary arrays before release.
Registry refs/tombstones retain no large inspection workspace or raw descriptors.

## Shared resources and digest

The unchanged active native ceiling is1MiB per launch. Account explicitly for
one maps arena <=576KiB, one reusable streaming scratch <=64KiB, owner/JNI/control
state, object/layout indexes and relocation work. Large layouts may stream; do
not allocate512 full ELF layouts or reset counters to fit. Retained native owners
remain <=16KiB and tombstones <=256 bytes, with four live/256 issued limits.
Immutable compiled recipe storage is separate, bounded and validated; it cannot
hide mutable per-launch scratch.

Use the existing one512-occurrence/2GiB cumulative work owner and512MiB file cap.
Every file hash retains its existing charges. Each mapped-object verification or
reverification additionally charges one occurrence and every compared mapped byte
to those same totals, including defined-zero and relocated bytes. Failed work is
charged conservatively before access. There is no second budget or reset between
objects/stages/execs. Exceeding either bound or the original10s startup refuses.
Boundary arithmetic does not prove maxima fit actual time or whole-runtime memory.

After complete comparison and conclusive inspection cleanup, an internal closure
record may use exactly ES_PRIVACY_CLOSURE_1's existing ordered object identity/file
digest encoding. Comparison authorizes those records; it does not replace their
content digests with memory hashes or change ES_PRIVACY_IDENTITY_1. Partial or
unsupported closure produces no successful digest. Nothing crosses JNI as raw
memory, mappings, addresses, descriptors or an admission boolean.

## Acceptance and qualification limits

RED must reach the missing closure behavior through actual production JNI,
PrivacyLaunchOwner and real FORK/root correlation using an invented credential-free
compiled fixture. Preserve that source and exact commands. GREEN must verify a
complete invented dynamic closure, with independent expected mapped bytes and
relocation results, complete object/digest inputs and all cleanup. It must still
observe mandatory no-CHALLENGE/no-FinalAdmitted and final owned process cleanup.

Adverse controls include private executable-page mutation with unchanged file
hash/maps; valid relocated RELRO versus altered target; missing/extra object;
split/overlapping/tail/zero-fill and ambiguous layout; different script under the
same interpreter; unexpected executable/anonymous mapping; early constructor or
IFUNC mutation/fork; later exec/dlopen; a thread delayed from joining group stop;
wrong/non-child stop observation; external continue treated as invalid/outside
the established preconditions without claiming reliable ABA detection; Java
reaper coexistence; EOF/short-read/EINTR/overflow, original deadline/cancel at
acquire/read/close; held read and shortened close; descriptor-number reuse;
sticky uncertainty; zero retained arenas and shared count/byte bounds. Distinguish
real kernel/process controls from narrow deterministic syscall fault wrappers.

Non-author review must inspect a fixed candidate and independently reproduce
mapped-memory versus file/maps distinctions. Required focused and combined Java,
distribution, targeted mutation and G00 gates remain. Actual installed kernel/
LSM/JDK/loader/guard/client evidence, descendant control, continuation, crash
collectors, whole-runtime resources and complete Oracle/PostgreSQL/orapki
qualification remain required before any release admission.
