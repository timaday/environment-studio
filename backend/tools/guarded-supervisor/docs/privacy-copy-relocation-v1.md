# Bounded COPY initialization-image comparison

This lead-owned extension specifies the next implementation prerequisite for
[direct-root closure](privacy-root-closure-v1.md). It does not qualify the installed
psql/SQL*Plus/JDK families, constructor history, lookup scope or continuation.
Production recipes remain absent; internal success still ends INSTALLATION without
CHALLENGE/FinalAdmitted. Existing JNI/digest/owner interfaces and product scope stay.

## Closed form and compatibility

Private recipe version2 permits a distinct COPY_INITIAL_IMAGE_V1 byte kind;
version1 retains its existing vocabulary and refuses COPY. Other version2 meanings
and limits are inherited unchanged. The representation stays native/private and
immutable, with independently checked static extents. No peer field, runtime
setter, Java array, path label or observed pointer supplies policy.

The initial subset is a direct ELF main executable destination (ET_EXEC or ET_DYN)
and one distinct admitted ET_DYN defining object. Both symbols are defined
STT_OBJECT/STB_GLOBAL/STV_DEFAULT with ordinary section indexes, positive equal
sizes1..65536 bytes and exact supported non-hidden symbol versions. COPY addend is
zero. Weak/unresolved, unversioned, GNU_UNIQUE, ABS/COMMON/TLS/IFUNC, unequal-size,
nonzero-addend and larger forms refuse until separately implemented. These are
implementation stages, not a reduced advertised client matrix. The first real
motivation is an externally inventoried versioned8-byte COPY; other actual client
COPY and loader requirements remain outstanding.

Every record fixes destination object and RELA entry/table identity, r_offset,
r_info/index and addend; exact reference symbol metadata/name/version; defining
object and exact defining symbol metadata/name/version; source/destination object
relative extents and length. Validate those facts against admitted file metadata
before memory access. Destination offset equals reference st_value and r_offset;
source offset equals defining st_value. COPY length equals both complete symbol
sizes; a contained prefix or shifted subspan is not this form. The main
executable's same-named symbol is the destination, never its own donor. Require a
unique eligible defining DSO in the complete admitted object set; a second eligible
definition or unsupported lookup case refuses, never first-name-match. This subset
check does not prove an installed loader's effective search scope or interposition.

Derive each address from its object's independently established load bias and
validated offset. Check integer/address/offset conversions, ends, symbol size,
PT_LOAD containment, file/zero-fill boundaries and every split/page crossing.
Retain ordinary file-image/BSS/permission coverage. Neither endpoint can be
reclassified as ORDINARY_DATA_NX or an arbitrary mutable interval.

## Independent expected bytes

COPY consumes the defining object's independently synthesized initialization image
after its declared supported non-COPY relocations. Its complete source span has
FILE/ZERO/LITERAL/existing scalar RELOCATION coverage. Literals retain independent
qualified or invented-fixture provenance; no current/prior peer can populate them.
An embedded relocated pointer is copied unchanged, never rebased at the destination.
Actual donor bytes cannot supply expected bytes for the destination.

Source byte dependencies are explicit record/extent references, checked against the
same immutable recipe. They precede COPY evaluation; table iteration is not an
implicit model of loader order. For this first form refuse COPY-of-COPY, cycles,
unsupported source relocations/mutable state, overlapping COPY destinations,
source/destination overlap and competing destination writes. A scalar formula
using a derived destination address does not itself consume destination bytes.
Required donors retain full ordinary mapped/file identity verification and their
unchanged ordered file digests.

Compare both actual donor and destination spans with that independent expected
image under the original stopped owner. This requires each still to have the
specified initialization bytes at comparison time. If either has changed, refuse;
if both have changed identically, also refuse. Equality cannot establish historical
loader writes, constructor behavior or absence of change-and-restore. The existing
exclusive-control condition and missing full-graph/lifetime stages remain mandatory;
no record boolean can assert that an unobserved initialization phase was safe.

## Original resources and cleanup

Stream through existing scratch within the1MiB active ceiling; no symbol-sized
allocation, per-COPY owner or second layouts/cache pool. COPY/dependency records and
all referenced metadata consume the existing65536-record/8MiB immutable limits.
Before COPY source synthesis/recheck, reserve one occurrence and twice its length
from the original512-occurrence/2GiB budget, including zero/literal spans. These
conservative extra charges cover expected source synthesis and actual donor
recheck; destination bytes retain their normal mapped-object charge. Repeated
COPY source work is charged again even when ordinary donor verification already
passed. Existing file-hash and any further mapped-verification charges remain;
no refund, hidden budget or reset. Validate multiplication before reservation.

Hold the same primitive claim, stopped acquisitions, hash owner, cancellation and
absolute startup clock throughout. Check original authority before/between source
and target chunks and after returning work. Held reads retain storage/descriptors
until actual return; shortened close cannot free them. Attempt subordinate cleanup,
preserve first refusal and sticky close uncertainty, wipe temporary/failed output,
and perform exact owned termination. COPY adds no continuation or secret input.

## First acceptance and later qualification

Actual production JNI/PrivacyLaunchOwner/FORK with an independently invented ELF
loader, donor and main executable must reach meaningful unsupported-COPY RED.
GREEN independently verifies nonzero bytes, zero-fill and a relocated pointer at
both endpoints, complete object coverage/digest and actual cleanup, while still
ending INSTALLATION. A fixture loader's declared relocate-then-copy behavior is
valid evidence for this internal mechanism only, never a replacement glibc client.

Adverse examples: donor-only, destination-only and identical two-endpoint changes;
wrongly rebased pointer; wrong donor/version/index/size or a second eligible DSO;
missing donor hidden as ordinary data; altered metadata/file bytes; version1 COPY;
zero/unequal/65537-byte extents; overflow, split-map escape and conflicting writes;
COPY dependency/cycle and unsupported TLS/lazy/IFUNC source; copy-before-source-
relocation; initializer changes after copy; count/byte boundaries, deadline/cancel
between endpoints, held return and reused descriptor uncertainty. Include valid
unaligned/page-crossing and65536-byte boundaries within complete declared coverage.
An initializer which acts before PREPARE must not gain full-graph authority merely
because it restores matching bytes. Preserve existing no-admission controls.

Record actual RED/GREEN, independent expected bytes, phase/ownership oracles,
compiled guard mutants and fixed non-author review. Run affected native and
required combined gates at their assigned boundaries. Actual effective loader/
provider selection, unequal/unversioned COPY, TLS/IFUNC, initializers/threads/exec/
dlopen, trusted distributions, collector policy and whole-runtime/client resources
remain required. No installation entry follows from this fixture extension.

## Primary grounding and deliberate subset

The [AMD64 ABI relocation table](https://refspecs.linuxfoundation.org/elf/x86_64-abi-0.99.pdf)
defines COPY as type5 without a scalar field/formula. Upstream
[glibc2.39 amd64 handling](https://raw.githubusercontent.com/bminor/glibc/glibc-2.39/sysdeps/x86_64/dl-machine.h)
copies the smaller symbol extent, while
[COPY lookup](https://raw.githubusercontent.com/bminor/glibc/glibc-2.39/elf/dl-lookup.c)
skips the main executable. This first equal-size/zero-addend/versioned subset is a
conservative design choice; it is not a claim that the ABI forbids other cases or
that upstream source qualifies the installed patched loader. Initialization/lifetime
risk remains separate from current byte comparison.
