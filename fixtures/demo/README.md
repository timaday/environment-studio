# Synthetic application fixture

This invented XML family exists to illustrate many-document comparison and
independent before/after expectations. It is not the user's actual schema and
must never be used to infer real application rules or database locators.

Three logical records: nodes, workloads and endpoints. One node initially owns
two workloads; the proposed target explicitly creates two nodes and moves one
workload to the second. Endpoint is an external reference, not a managed load
balancer. IDs and application names change explicitly. All addresses use the
reserved `.invalid` domain. No secrets or real connection properties exist.

The definition JSON passes the **draft shape** only. Identity scopes, concrete
DB inventory locators, role modelling, relation mapping and structural writer
capability implementations are deliberately still missing. It cannot be
published or exported without D01 semantics/mapping qualification. The named
`demo.*` capabilities are illustrative contract IDs, not installed plugins.

`profile.json` is an illustrative value-free structural draft bound to this
exact definition file digest. It has logical labels and input declarations,
not environment values. Java semantic publication and persistence are not
implemented. The target XML was authored independently, not generated by the
starter's writer (there is no writer).
