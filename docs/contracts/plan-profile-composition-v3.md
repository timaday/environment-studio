# Internal shared v3 profile reuse

Use the shared plan owner for whole/partial v3 reuse. A separate trusted
Workspace.profileV3 port must resolve a currently qualified exact v3 profile
against the selected definition. Its default refuses. The eventual versioned
workspace adapter delegates to V3PlanWorkspace's fresh selected/original
definition and profile checks; no v2 publication result represents v3 readiness.
No runtime wiring, HTTP route or publication availability is introduced here.

Before preview or composition, freshly verify the complete retained target
against original XML, original/decision pins and draft through the controlled v3
content adapter. A claimed graph or matching revision alone is insufficient.
Use actual V3ProfileComposer for physical closure, affected derivation IDs and
explicit existing/create/cancel choices. An empty roots list selects the whole
profile; partial roots preserve unselected destination siblings. Only physical
slots/relations are reusable; target values and fresh full recomputation determine
computed groups. New slots have explicit unresolved values and placements.

CompositionPreview retains a separate optional complete v3 preview. Its physical
component must equal the exposed dependencies. Legacy construction supplies no
v3 preview and cannot authorize v3 composition. V3 preview digests use a separate
ES-PLAN-COMPOSITION-PREVIEW-3 domain and bind the complete versioned preview,
including affected derivations. Direct mutation identity also binds that detail;
v2 digest inputs and bytes remain unchanged. A fresh preview must equal the
submitted direct preview or match the command's digest before mutation.

Direct, admitted-view preview and command composition use the original lease,
revision, generation and cancellation flag throughout verification, workspace
lookup, composition and final installation. The one shared scratch stays held
until work exits; nested calls do not renew it. Closing/invalidating the original
view/command admission or retiring the plan cannot admit a late result. Command
v3 composition and its subsequent v3 materialization share the command admission's
original cancellation flag; closing that admission signals it without releasing
scratch until execution exits. Existing v2 command completion/close behavior
remains unchanged; its work uses the original separate rendering control. New target handles are
installed with the draft for both command and direct composition. Replays return
the original acknowledgement without composing again. Target materialization
retains original Existing/Fresh provenance and independently compares actual XML
and complete derived evidence; unresolved target remains inspectable but blocked.

Acceptance uses independently invented XML/profile fixtures: whole/partial
preview, affected derivations, explicit Existing/Fresh choices, unresolved values,
unchanged siblings, target edits followed by reuse, fresh group recomputation,
stale publication/preview/revision/proof and late cancellation. Original v2 tests,
digests and readable history remain required controls. Current compiler refusal
and combined capacity qualification remain independent admission blockers.
