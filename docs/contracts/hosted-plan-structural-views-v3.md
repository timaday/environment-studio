# Hosted v3 structural and binding pages

This extends hosted-plan-physical-views-v3 with five POST routes under /api/v3/plans/{planId}: /views/relations, /views/draft, /views/containment, /views/placements and /views/bindings. It uses the existing controlled V3PlanPhysicalViews adapter. All physical-view ownership, admission, pin/reproof, original cancellation, deadlines, error and conclusive worker settlement rules apply unchanged. Both existing full scratch and the single semantic HTTP record must be admitted before body access; no new pool, metadata slot, physical permit or cached page is introduced. Actual v3 compilation/publication stays incomplete; test witnesses confer no runtime availability.

Requests and successful responses retain the exact existing plan-view-v1.schema.json shapes and PlanViewReader grammar. Relations takes {revision,side,offset,limit}; draft and containment take {revision,offset,limit}; placements takes {revision,documentId,projectionId,offset,limit}; bindings takes {revision,entity,offset,limit}. Side is current|target; Existing references are opaque handles and Fresh references explicit slot/type. Binding offset is 0..256; other offsets are 0..50000; all limits 1..100. No defaults, root aliases, duplicate properties, disclosure/reveal override, filters, model selectors or client authority. Requests retain 16 KiB/depth4/128tokens/original10s bounds; full responses retain128MiB/original30s encoding/output/flush bounds. These explicit read actions do not increment revision or consume command replay IDs.

Relations returns complete physical-only {relationId,from,to} rows for the selected graph, preserving final provenance and original Existing handles after identity changes. Missing target refuses INCOMPLETE_TARGET, never empty success. Draft returns only explicit typed decisions with existing closed disposition/field/reference/placement shapes; no inferred retained override, and masked/unresolved/absent values never become entered text. Containment lists explicit typed decisions even when target is incomplete. Placements lists eligible original-parent {documentId,sourceDigest,elementIndex} coordinates under the declared document/projection; callers cannot supply XML paths or infer parents from labels. Later commands still revalidate coordinates. All pages preserve complete totals, deterministic ordering, bounded pages and null nextOffset beyond the end; no computed relation is included in a physical total.

Binding rows exactly follow hosted-plan-context-v1: {fieldId,token,current,target,change,currentLocations,targetLocations}. Resolve from controlled original content, target provenance and explicit draft decisions; preserve value/masked/absent/unresolved/unavailable states and masked value states and complete versus unavailable location counts. Tokens remain stable across identity edits and use declared field IDs plus existing allocated handles; reference occurrences resolve to the target identity field. No getter allocates new identities, exposes raw logical keys or revives retired Fresh handles. SECRET, UNKNOWN and unreadable values expose no text, lengths or value hashes. Empty PUBLIC text stays a value, and missing required target decisions stay unresolved. Pages do not grant location/document disclosure or export authority.

Every response freshly re-verifies complete original content and any retained target through the original admitted view. Retained current data after failed inspection is viewable without restoring inspection/export validity. After pinning, successful and error responses retain that same revision/inspection pin through output; a replacement, retirement or cancellation aborts rather than switching to lease-only verification. No raw/formatted/placeholder document, concrete location, capture, computed or validation route is introduced by this slice.

Acceptance uses independently invented XML/model evidence: explicit retain/create/remove drafts; existing/Fresh binding references with masked, absent and unresolved values; exact original placement coordinates used in a creation command; physical relation endpoints preserved after identity changes; incomplete target versus readable explicit draft; stable totals and beyond-end pages; foreign/V2/stale/closed-body refusal; scratch and semantic rollback/cancellation through held output. Actual MockOIDC/CSRF/socket tests must drive returned coordinates/references into typed commands. Existing v1 behavior, digest authority and compiler refusal remain unchanged.
