# Hosted v3 semantic commands

Implementation target; this contract is not runtime qualification. Extends the initial v3 plan routes with POST /api/v3/plans/{planId}/commands. Uses the existing closed plan-command-v1 request vocabulary and the v3 acknowledgement reply; no caller-selected model version, publication authority, target XML or computed membership. The current v3 compiler remains Incomplete and test witnesses confer no availability. Existing v1 routes stay fixedV2.

Require original live lease, expected Host/Origin/CSRF, configured hosted composition and immutable V3 ownership before any scratch/HTTP record admission, request-body access, async start or service side effect. Pure ownership still permits retained command replay metadata; the existing command admission/execute path determines whether an exact replay or new command is eligible. Do not pre-resolve handles/preview state in HTTP. Successful commands return200 original Ack with exact decimal-string revision; exact replay retains its original Ack, collisions conflict and wrong-version resources refuse404. Original typed command semantics, logical revision identity, deterministic derived recomputation and physical-only profiles remain in Java.

Before reading any command bytes, reserve the existing single full command/view/materialization scratch through reserveCommand(lease,planId,V3). No second domain scratch budget, waiting queue or new physical observation. Retain that exact CommandAdmission until worker closure. To make HTTP cleanup observable after application closure, add one separately bounded semantic HTTP record to V3PlanTransfers; at most one such record and nine total records (four shared metadata slots, four credential HTTP records, one semantic record). The semantic record does not reserve another metadata slot or physical permit. Record admission and core admission are immediate; if either fails, release only conclusively acquired application resources and settle an unstarted record conclusively. No body/output/startAsync before both are owned. Terminal HTTP uncertainty retains the minimal semantic record and quarantines its original lease, even after core scratch closes; it is not silently evicted or converted to success to admit another transfer.

The closed transport adds a semantic-body mode, not arbitrary caller-supplied limits: 134217728 wire bytes and one original30s absolute body deadline, with existing PlanCommandReader depth16/token/semantic limits. Existing small bodies remain16384 bytes/10s. No raw complete-body copy; the original scratch owns decoded command values. Body callbacks and readiness waits follow the existing nonblocking ownership contract. Only typed Ack may leave the semantic command worker; its reply stays32768 UTF8 bytes under the original30s encoding/output/flush deadline and original lease/version verification. A command action owns its existing cancellation authority; malformed or oversized commands refuse without a successful mutation. No success is fabricated from partial JSON or a committed-but-undelivered Ack.

The sole async completion owner receives workerClosed only after body, exact CommandAdmission and encoded/output buffers are actually closed/wiped. Listener/setup/closure/completion uncertainty follows hosted-plan-http-v3 and plan-transfers-v3. Pre-transfer refusals use the existing no-body safe-code header branch. Owned failures use the same bounded closed JSON response; do not renew an output deadline, reread credentials or append a second response after output acquisition. Existing core session cleanup and mixed-family retry guards remain.

Acceptance: actual shared-v3-service command changes and exact replay; wrong-version/foreign/revoked before admission/body; busy full scratch and busy semantic HTTP record before request input; malformed request leaves the plan unchanged; late original lease loss refuses mutation/output; successful worker retains scratch through response then releases it exactly once; actual partial-body HTTP cancellation/recovery and real MockOIDC/CSRF. Independent mock XML controls verify an explicit PUBLIC field change materializes and recomputes groups, while v2 historical behavior and retained replay remain unchanged. This route does not introduce comparison, capture/reuse, validation, export or readback endpoints.
