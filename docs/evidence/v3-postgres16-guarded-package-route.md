## Behavior and scope

The hosted V3 application exposes an unqualified package-candidate download route:
`POST /api/v3/plans/{planId}/package-candidates/guarded`. The request body is a
closed JSON object containing only `revision` and `inputFingerprint`. The caller
cannot supply destination, binding, client, server, template, policy or publication
metadata; those are taken from the pinned plan admission and trusted destination
configuration.

The route rechecks ownership, V3 plan admission, revision, inspection evidence,
complete target materialization, input fingerprint, destination physical identity,
binding engine/storage, protected document-content policies and the configured
PostgreSQL 16.11/psql 16.11/linux-amd64/template tuple before sending archive
bytes. Unsupported or absent tuples refuse before streaming. Successful responses
return `application/zip`, `Cache-Control: no-store` and
`X-Environment-Studio-Qualified: false`.

The downloaded archive contains the existing deterministic guarded package members:
`manifest.json`, `payload.json`, `transaction.sql` and `instructions.txt`. The
application still does not execute SQL, persist a package or mark
`exportAvailable=true`. Operational export, native supervisor execution, TLS/client
qualification and release evidence remain open.

Acceptance examples:

- a complete inspected/materialized/validated V3 plan on the configured PostgreSQL
  16.11 mock destination downloads a ZIP with the expected four members;
- the manifest pins plan id, revision, input fingerprint, destination identity,
  server version `16.11`, client `psql` `16.11` and template
  `postgresql16-text-v1`;
- payload records come from the actual mock plan payload, not a demo fallback;
- transaction SQL is generated by the admitted PostgreSQL 16 template, contains
  the `160011` version guard and does not contain COMMIT or ROLLBACK;
- stale revision requests refuse with `CONFLICT` before any ZIP is sent;
- unsupported or incomplete export-client configuration refuses package availability.

## Review correction — PKG-QA-001
